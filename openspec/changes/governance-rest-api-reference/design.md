# Design: governance-rest-api-reference

Read at development `d767c282`.

## Context

- `appinfo/routes.php` registers 181 route entries under `/index.php/apps/launchpad/`, served by the controllers in `lib/Controller/` (for example `DashboardApiController`, `WidgetApiController`, `TileApiController`, `DashboardShareApiController`, `PublicShareController`). They follow ADR-002 (hydra `openspec/architecture/adr-002-api.md`: `/index.php/apps/{app}/api/{resource}`, standard verbs, `message` on errors, Nextcloud authentication only).
- Controllers carry auth attributes (`#[NoAdminRequired]`, `#[PublicPage]`, `#[AuthorizedAdminSetting]`) and `@spec` docblocks, but no response shape annotations.
- `composer.json` defines `check:strict` as a loop over lint, phpcs, phpmd, psalm, phpstan and tests. `scripts/` holds the repo's own checks (`check-manifest.js`, `lint-initial-state.php`).
- The documentation site is Docusaurus under `docs/` (`docs/docusaurus.config.js`).
- Nextcloud apps publish `openapi.json` at their repository root; Nextcloud's own dashboard app does (`apps/dashboard/openapi.json`).

## Decisions

### D1: Generated, never hand-written

Task 1 tries `nextcloud/openapi-extractor` on three LaunchPad controllers. If it documents LaunchPad's index.php JSON routes with their attributes, it is the generator. If it does not, `scripts/generate-openapi.php` reads `appinfo/routes.php`, reflects each controller method's parameters, attributes and `@return` or a `@psalm-return` shape, and writes OpenAPI 3.1. Either way the file is an output, regenerated by one composer script.

### D2: Two stability levels

Every operation carries `x-launchpad-stability: public` or `internal`. Public in this change: dashboard CRUD and listing, placements and tiles, sharing, public links, export and import. Everything else starts internal. A public operation changes only with a deprecation notice in the changelog; internal ones may change freely.

### D3: The drift check

`composer lint:openapi` regenerates the file into a temporary path and fails when it differs from the committed `openapi.json`, or when a route name in `routes.php` has no operation. It joins `check:strict`, so a new route without documentation fails locally and in CI.

### D4: Authentication is documented, not added

The reference documents Basic authentication with a Nextcloud app password, as Nextcloud supports for app routes, and the `OCS-APIRequest: true` header. No new token flow (ADR-002).

## Declarative-vs-imperative decision

Documentation generated from code; no schema register involved.

## Test plan

- The drift check itself: a PHPUnit or script test with a fixture routes file where one route lacks an operation.
- Validate `openapi.json` against the OpenAPI 3.1 schema in CI.
- Manual check recorded in the PR: `curl -u user:app-password https://<instance>/index.php/apps/launchpad/api/dashboards` matches the documented response shape.
