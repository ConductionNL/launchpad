# AGENTS.md

Guidance for coding agents working in this repository. Human contributor docs
are in [CONTRIBUTING.md](CONTRIBUTING.md), [DEVELOPMENT.md](DEVELOPMENT.md) and
[docs/development.md](docs/development.md).

## What this app is

LaunchPad is a Nextcloud app (app id `launchpad`, PHP backend in `lib/`, Vue
frontend in `src/`) that turns the Nextcloud dashboard into multiple
personalized dashboards with drag-and-drop widgets, custom shortcut tiles and
conditional visibility rules. Admins can roll dashboards out to groups as
templates; see [README.md](README.md) and [appinfo/info.xml](appinfo/info.xml).

## Setup

- Development happens in the nextcloud-docker-dev environment with this app
  mounted into the Nextcloud container, as described in
  [DEVELOPMENT.md](DEVELOPMENT.md).
- [docker/docker-compose.yml](docker/docker-compose.yml) is an evaluation stack
  (Nextcloud with LaunchPad and OpenRegister, PostgreSQL, Redis):
  `docker compose -f docker/docker-compose.yml up -d --build`, then open
  `http://localhost:8080/apps/launchpad/`.
- [launchpad-compose.yaml](launchpad-compose.yaml) is a demo environment, not a
  development environment: it does not mount your working copy.
- Install dependencies with `composer install` and `npm ci`. Both set
  `git config core.hooksPath .githooks` (composer `post-install-cmd`, npm
  `prepare`).

## Build

```bash
npm run dev      # development build
npm run watch    # development build, rebuilds on change
npm run build    # production build, includes the embed SDK (npm run build:embed-sdk)
```

## Test

```bash
composer test:unit         # PHPUnit, suite in tests/Unit (config: phpunit.xml)
npm test                   # Vitest (config: vitest.config.js; src/**/__tests__, tests/vitest)
npm run test:e2e           # Playwright against a running instance (config: playwright.config.ts, tests in tests/e2e)
composer test:integration  # Newman run of tests/integration/launchpad.postman_collection.json
```

Coverage: `composer test:coverage` (PHP) and `npm run test:coverage` (Vitest).

## Lint and quality

```bash
composer check          # lint, phpcs, psalm, test:unit
composer check:strict   # full PHP suite: lint, lint:initial-state, lint:openapi,
                        # lint:spec-annotations, lint:licenses, phpcs, phpmd, psalm, phpstan, test:all
composer cs:fix         # auto-fix PHP code style
npm run lint            # eslint, then check:manifest, lint:initial-state, lint:translation-domain
npm run stylelint       # styles in src/ and css/
npm run format          # prettier check
npm run check:l10n-parity
```

The API description in [openapi.json](openapi.json) is generated by
`composer openapi:generate` and checked by `composer lint:openapi`.

## OpenSpec flow

Behaviour is specified in [openspec/](openspec/) (project rules in
[openspec/config.yaml](openspec/config.yaml)).

1. Propose a change in `openspec/changes/<name>/`: `proposal.md`, `design.md`,
   `tasks.md` and delta specs in `specs/<capability>/spec.md`, following the
   existing changes in that folder.
2. The current, accepted behaviour lives in `openspec/specs/<capability>/spec.md`.
3. When a change is done it moves to
   `openspec/changes/archive/<YYYY-MM-DD>-<name>/`.

The pre-commit hook in [.githooks/pre-commit](.githooks/pre-commit) regenerates
`docs/features.json` when staged changes touch `openspec/specs/`.

## Repo conventions

- Pages are manifest configuration: `src/main.js` builds the router from the
  `pages` in [src/manifest.json](src/manifest.json) (via `routesFromManifest`),
  merged with per-change fragments in [src/manifest.d/](src/manifest.d/).
  Validate with `npm run check:manifest`.
- Custom widget types are registered in one place,
  [src/constants/widgetRegistry.js](src/constants/widgetRegistry.js); keep
  `EXPECTED_TYPES` in
  `src/constants/__tests__/widgetRegistry.completeness.spec.js` in sync (see
  [DEVELOPMENT.md](DEVELOPMENT.md)).
- OpenRegister is optional at runtime and is not an install-time dependency
  (see `appinfo/info.xml` and the "Runtime-only OR consumption policy" in
  [docs/architecture.md](docs/architecture.md)).
- Routes are declared in [appinfo/routes.php](appinfo/routes.php).
- User-visible strings are translated; translations live in [l10n/](l10n/).

## Commit format

Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`), present
tense, imperative mood, first line at most 72 characters, as described in
[CONTRIBUTING.md](CONTRIBUTING.md). Pull requests target `development`.
