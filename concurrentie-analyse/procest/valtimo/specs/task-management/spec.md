# Task Management -- Valtimo

## Purpose
Manages user tasks generated by BPMN processes. Tasks represent work items that require human action -- filling out a form, making a decision, or reviewing a document. The task system handles assignment, claiming, delegation, due dates, and task completion with data submission.

## Architecture Overview
- **Backend module**: `core/` (task service layer wrapping Operaton task API)
- **Frontend modules**: `task/` (list, detail, assignment) and `task-management/` (configuration) Angular libraries
- **Engine**: Tasks are native Operaton user tasks -- Valtimo adds assignment logic, form linking, and access control
- **Portal**: Portaaltaak module extends tasks to citizen-facing portals

## Data Model

### Task (Operaton-managed, enriched by Valtimo)
| Field | Type | Description |
|-------|------|-------------|
| id | String | Operaton task ID |
| name | String | Task name (from BPMN definition) |
| assignee | String | Currently assigned user ID |
| candidateUsers | List<String> | Users who can claim the task |
| candidateGroups | List<String> | Groups who can claim the task |
| dueDate | Date | Task deadline |
| followUpDate | Date | Follow-up reminder date |
| createTime | Date | When the task was created |
| processInstanceId | String | Parent process instance |
| processDefinitionId | String | Process definition reference |
| taskDefinitionKey | String | BPMN element ID |
| formKey | String | Linked form reference |
| description | String | Task description |
| priority | Integer | Priority level |

### TaskOpenResult (Valtimo enrichment)
| Field | Type | Description |
|-------|------|-------------|
| task | Task | The Operaton task |
| processLink | ProcessLink | Linked form/plugin action |
| formDefinition | JSON | Form.io definition (if form-linked) |
| prefilledData | JSON | Prefilled form values via value resolvers |

## Business Logic

### Task Creation
1. BPMN process reaches a user task element
2. Operaton creates a task instance with assignment from BPMN definition
3. Assignment sources: fixed user, candidate group, expression (`${assignee}`)
4. Valtimo enriches with ProcessLink (form/form-flow/plugin action)

### Task Assignment Flow
1. **Direct assignment**: Task assigned to specific user in BPMN model
2. **Group assignment**: Task available to candidate group members
3. **Claiming**: User claims an unassigned task from group pool
4. **Delegation**: Assigned user delegates to another user
5. **Unassignment**: Task returned to the pool

### Task Completion
1. User opens task -- form prefilled via value resolvers
2. User fills in form data and submits
3. Form submission validated against Form.io rules
4. Value resolvers write data to targets (`doc:`, `pv:`)
5. Task marked as completed in Operaton
6. Process continues to next BPMN element

### Task List
- Paginated task list with filtering by assignee, candidate group, process definition
- Configurable columns per case type
- Bulk assignment support
- Search by task name, case reference

### Portal Tasks (Portaaltaak)
- Extends tasks to citizen-facing portals (NL Portal)
- Creates external task representations for self-service
- Citizen completes task in portal; result flows back to Valtimo
- Bridges the internal case worker and citizen worlds

## Comparison Notes -- Valtimo vs Procest

### Procest approach
- Tasks managed via OpenRegister objects with status tracking
- Assignment via Nextcloud user/group system
- n8n workflows trigger task creation and state changes
- Simpler model: tasks are data objects, not engine-managed entities

### Valtimo advantages
- Engine-managed tasks with built-in lifecycle (create, assign, claim, complete)
- Candidate group claiming -- tasks available to pools of users
- Delegation support
- Due dates and follow-up dates with reminders
- Task-level forms with prefill and submission binding
- Priority levels
- Portal task bridge for citizen self-service

### Valtimo disadvantages
- Tasks tightly coupled to BPMN -- cannot create ad-hoc tasks outside a process
- Task model is Operaton-native -- limited customization of task fields
- No Kanban/pipeline view for tasks (list-only)
- Task completion requires active process instance -- orphaned tasks if process fails
